# W# 0.1.51

The findings of the audit of 11.11.2026 fixed: what a server keeps of a call, how a plugin is
loaded and what the host takes from it, the files a program writes, the links a page opens.

## What changed

- **Secrets of a call** (W-1): the line of a call in the journal and in the log (`tool NAME
  key=value ...`) shows a secret field as `key=***`, whatever its value looks like; it showed a
  password or a token of letters and digits. A field is secret by one rule for that line, the
  arguments and the answer kept: a name a source gives (`Source::secrets`), or any name that
  holds `password`, `token`, `authorization` or `secret` (`new_password`, `api_token`), where
  only the exact names were hidden before.
- **Loading a plugin** (W-2): a DLL is loaded by its absolute path, and the DLLs it imports are
  searched in its own folder, in the folder of the program and in the system folder alone, never
  in the current folder or the PATH. A plugin that needs a DLL of another place ships it next to
  itself or next to the program.
- **The folder of the plugins** (W-7): a program without a folder `plugins` loads the DLLs next
  to its executable in a debug build alone (a build of a workspace); a release build loads none.
- **A plugin of another build** (W-23): a `ww_plugin_abi` that gives no text is refused, not
  read.
- **The tools of the window** (W-4): a call the window did not answer in 30 seconds is never run
  later; it was run when the window came back (out of a dialog), after its caller was told that
  it failed. A call the window is already working on has 30 seconds more.
- **Markdown pages** (W-3): quotes and lists nest 32 deep at most (`markdown::MAX_NESTING`); the
  text of deeper ones joins the blocks around them. A page of thousands of `>` ended the program
  with a stack overflow.
- **Links of a page** (W-15): a web link is `http://`, `https://` or `mailto:`; a link of any
  other scheme but `file:` (`javascript:`, `data:`, the scheme of some program) is opened
  nowhere, and the status bar says so.
- **The HTTP transport** (W-14): `HttpServer::start` refuses a token shorter than 32 characters,
  an empty one too (`InvalidInput`); the tab and the command line never passed one.
- **The stdio transport** (W-13): a line longer than 4 MB is not read whole, and a line that is
  not UTF-8 no longer ends the server: each gets an error answer and the next line is served.
- **The stable interface** (W-9, W-8): a function of the host that fails inside (a tool that
  crashes under `call_tool`, a file, the cache) gives its failure to the plugin and no longer
  ends the program; a picture larger than a texture of the renderer or than 256 MB is refused,
  with the last picture kept and one line in the log.
- **Files written** (W-17): `ww_base::files::write` writes through a temporary neighbour of a
  name of its own (`<name>.<process>-<number>.tmp`), synced to the disk before it replaces the
  target and removed when the write fails. It took `<stem>.tmp`, which wrote over a file
  `report.tmp` of the user next to `report.json`. `ww::store` and the configuration of the MCP
  server write through the same function (`write_disk`); the configuration was written in place.
- **The journal and the detailed log** (W-12): the arguments of a call are kept as the answer
  is, cut to their first 16 KB; the details of the calls stop for the day once the log holds
  64 MB, with one line that says so.
- **A configuration that did not read** (W-16): the tab of the server never writes over it, not
  after a start either (the token it made was a change that wrote the defaults over the file);
  the configuration lives in the tab until **Save as** or another file opened.
- **The storage of a page** (W-18): what a program writes wins over a file of the same path read
  over http, which was read again after a save; bytes that are not UTF-8 are refused, not stored
  with their wrong bytes replaced. The prefix of the keys is as it was.
- **The demo** (W-6, the demo alone): settings that are there and do not read load no DLL of the
  folder of the plugins; they meant "every DLL is trusted".
- **Documents and checks** (W-19, W-21, W-22): the sizes of `ww_host`, `ww_tool`, `ww_option` and
  `ww_tools` in `docs/stable.md`; the token of a run of CI reads the repository alone;
  `build-all.cmd check` runs the format of `examples/ww-grey` and clippy of W# for the browser
  too; pulldown-cmark 0.13.6.

## For a program on W#

- No interface changed: the traits, `ww.h` and the public signatures are the ones of 0.1.50, and
  no text of the interface was added or changed. New functions: `ww_base::files::write_disk`,
  `wwmcp::log::detail`, `markdown::MAX_NESTING`, `wwmcp::log::DETAIL_DAY_LIMIT`.
- A release build needs its folder `plugins` (or the variable of `plugins_dir`): DLLs next to
  the executable are no plugins there.
- A plugin that imports a DLL found through the PATH or the current folder no longer loads.
- `McpPanel::saved` is `None` for a file that did not read.
